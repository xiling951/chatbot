# 本机运行与恢复

固定代码与虚拟环境在 F:/chatbot-runtime/AstrBot，项目脚本在 F:/chatbot/scripts。私有运行目录由本机忽略文件 config/runtime_root.local.json 定位，不提交该文件、密钥或数据库。

本机 Codex 打包环境会重定向部分 AppData 文件；普通登录任务看到的 C 盘父目录与代理进程看到的数据子目录并不相同。路径必须从已有 cmd_config.json 的实际文件位置解析，再固定给所有脚本；只解析上级目录会落到混合的虚拟视图。此次仅固定了已有 NTFS 目录的位置，没有复制、重置数据库或变更绑定。

当前用户登录任务 CompanionCore_Runtime 使用隐藏 PowerShell 包装器及独占文件锁启动观察/恢复进程，无须保持 Codex 聊天开启。它每 30 秒记录进程身份、本地管理页和适配器报告状态；不调用付费模型、不发测试消息，也不把适配器运行当成手机送达。STOP 存在时停止自动恢复和外发；启动脚本保留 STOP，不擅自恢复模型权限。

进程不存在时自动启动；本地页面连续三次失败才尝试重启已核对 PID/创建时间的本项目进程。15 分钟最多 3 次，超出退避，避免故障循环。启动与恢复使用同一个本机互斥锁。启动日志轮转到受控目录，观察及本项目命名日志保留 8 天，删除账本不参与淘汰。电脑休眠、退出登录和断网时不能保证持续在线，未修改电源设置。

预登记的进程退出恢复目标：120 秒内恢复本地管理页，另测一次真实模型和本人微信收发。进程退出演练不等于主机重启、网络中断或提供商故障已通过。实际测得结果和限制写入 reports/P6.md。

72 小时观察从首次后台有效记录 2026-10-27T02:14:06.266877Z 开始，30 秒采样，窗口右端不含，共预期 8640 个时隙。每时隙保守采用最差状态，缺样单列 unknown，不填成功；重启、维护、休眠缺口不从分母悄悄剔除。分别报告进程/管理页、适配器报告、真实模型样本与人工设备观察。未主动探测模型时保持 not_run，不推算模型可用率。7 个自然日试用尚未完成。

安装/更新当前用户登录恢复：powershell -File F:/chatbot/scripts/install_startup.ps1。检查：python F:/chatbot/scripts/runtime_watchdog.py --once；启停仍用 start.ps1/stop.ps1。关闭自动恢复可禁用登录任务，但人工停止服务请使用 stop.ps1，使 STOP 和主动撤销先持久化。实际登录触发仍待主机重启/重新登录观察，注册成功不等于已做开机验收。

观察统计：运行目录 Python 执行 scripts/availability_report.py --save。只统计已结束的 30 秒时隙，开放/未来时隙不计分；同一时隙采用最差状态，缺样保留 unknown，同时给可用率上下界。窗口未结束时明确 in_progress，不提前宣布达到 72 小时目标；本地状态不能推导模型或手机可用率。

后台观察循环也检查本机加密备份：清醒且登录运行时每 24 小时一份，失败后退避一小时，失败不停止观察。备份在 F:/chatbot-backups，保留 7 天，仅淘汰本项目精确命名的完整加密文件，不清除最新删除账本。休眠/关机期间不执行，因此 24 小时是在线条件下的 RPO 目标，非停机关机保证。流程与同机解密限制见 backup_restore.md。
